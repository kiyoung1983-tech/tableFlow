# Spring 풀스택 공통 기능 구축 상세 기록

작성일: 2026-08-16 (Asia/Seoul)

## 1. 작업 목표

초기 Todo 예제에 기능을 계속 추가할 때 Controller와 화면마다 같은 코드를 반복하지 않도록 다음 여섯 가지 기반을 구축했다.

1. 백엔드 전역 오류 처리와 도메인 예외
2. 프론트엔드 공통 API 클라이언트
3. Todo HTTP 통합 테스트
4. 요청 추적 ID와 공통 HTTP 로그
5. JPA 생성·수정 시간 감사와 공통 페이지 응답
6. OpenAPI 계약 기반 TypeScript 타입 생성

공통 코드는 하나의 거대한 `CommonUtil`에 모으지 않고 책임에 따라 `common/error`, `common/web`, `common/persistence`로 나눴다. Todo에만 해당하는 예외와 API 코드는 `todo` 패키지에 유지했다.

## 2. 공통 오류 응답

### 구성

- `common/error/ApiException.java`: HTTP 상태, 안정적인 애플리케이션 오류 코드, 사용자 메시지를 가진 기반 예외
- `common/error/GlobalExceptionHandler.java`: 모든 Controller에서 발생하는 예외를 RFC 9457 Problem Details로 변환
- `todo/TodoNotFoundException.java`: Todo 단건 조회 실패를 `404 / TODO_NOT_FOUND`로 표현하는 도메인 예외

오류 응답은 다음 필드를 공통으로 사용한다.

```json
{
  "type": "about:blank",
  "title": "Not Found",
  "status": 404,
  "detail": "Todo를 찾을 수 없습니다: ...",
  "instance": "/api/todos/...",
  "code": "TODO_NOT_FOUND",
  "traceId": "..."
}
```

입력 검증 실패에는 필드별 메시지가 추가된다.

```json
{
  "title": "Validation failed",
  "status": 400,
  "detail": "요청값을 확인해 주세요.",
  "code": "VALIDATION_ERROR",
  "traceId": "...",
  "errors": {
    "title": ["must not be blank"]
  }
}
```

요청 본문 검증, 메서드 파라미터 검증, 깨진 JSON 같은 Spring MVC 내장 오류도 `code`와 `traceId`를 갖도록 `handleExceptionInternal`에서 보강한다. 예상하지 못한 서버 오류는 상세 구현이나 스택 트레이스를 응답으로 노출하지 않고 `INTERNAL_SERVER_ERROR`로 반환하며 전체 예외는 서버 로그에 남긴다.

Spring Security 필터에서 발생하는 인증·권한 오류는 ControllerAdvice까지 도달하지 않으므로 `SecurityConfig`의 `AuthenticationEntryPoint`와 `AccessDeniedHandler`가 각각 `AUTHENTICATION_REQUIRED`, `ACCESS_DENIED` Problem Details를 직접 작성한다.

## 3. 요청 추적 ID와 로그

`common/web/RequestTraceFilter.java`가 모든 HTTP 요청에 한 번 실행된다.

처리 순서는 다음과 같다.

1. 클라이언트의 `X-Request-Id`가 안전한 문자와 100자 제한을 만족하면 그대로 사용한다.
2. 값이 없거나 올바르지 않으면 UUID를 생성한다.
3. 요청 attribute, 응답 `X-Request-Id` 헤더, SLF4J MDC에 같은 값을 저장한다.
4. 요청 완료 시 method, path, status, 처리 시간을 한 줄로 기록한다.
5. 요청 처리가 끝나면 MDC 값을 제거해 스레드 재사용 시 다른 요청으로 새지 않게 한다.

로그 예시:

```text
INFO [traceId:client-request-123] http_request method=GET path=/api/todos status=200 duration_ms=12
```

오류 응답과 로그에 같은 ID가 있으므로 사용자가 전달한 오류의 서버 로그를 찾을 수 있다. CORS의 exposed header에도 `X-Request-Id`를 추가해 브라우저 코드가 이 헤더를 읽을 수 있게 했다.

## 4. JPA 감사 시간과 DB migration

`common/persistence/BaseTimeEntity.java`에 다음 필드를 정의했다.

- `createdAt`: 최초 저장 시 자동 입력되고 이후 수정되지 않음
- `updatedAt`: 최초 저장 및 변경 시 자동 갱신

`PersistenceConfig.java`의 `@EnableJpaAuditing`이 Spring Data JPA 감사를 활성화한다. `Todo`는 `BaseTimeEntity`를 상속하며 생성자에서 시각을 직접 만들지 않는다. 시간 기록 책임을 Spring Data에 통일해 새로운 Entity에서도 같은 정책을 재사용할 수 있다.

기존 DB를 보존하기 위해 V1 migration을 수정하지 않고 `V3__add_todo_updated_at.sql`을 추가했다.

1. nullable `updated_at` 컬럼 추가
2. 기존 행은 `created_at` 값으로 채움
3. 최종적으로 NOT NULL 제약 적용

이 순서라서 이미 Todo 데이터가 있는 개발 DB에서도 migration이 실패하지 않는다.

## 5. 공통 페이징 응답

`common/web/PageResponse.java`는 Spring Data의 `Page<S>`를 외부 API DTO 목록으로 변환한다.

```json
{
  "items": [],
  "page": 0,
  "size": 20,
  "totalElements": 0,
  "totalPages": 0,
  "first": true,
  "last": true
}
```

`GET /api/todos`는 다음 파라미터를 받는다.

- `page`: 0 이상, 기본값 0
- `size`: 1~100, 기본값 20

목록은 기존처럼 `createdAt` 내림차순이다. 최대 크기를 100으로 제한해 실수나 악의적인 요청이 한 번에 너무 많은 레코드를 읽지 못하게 했다. 프론트 화면도 배열을 직접 받는 방식에서 `todoPage.items`를 사용하는 방식으로 변경했다.

단건 오류 처리를 실제로 사용할 수 있도록 `GET /api/todos/{id}`도 추가했다. 없는 UUID는 `TodoNotFoundException`으로 처리한다.

## 6. 프론트엔드 공통 API 계층

### 파일 역할

- `frontend/src/api/client.ts`: fetch 실행, JSON 직렬화, 성공 응답 파싱, 오류 변환, 요청 ID 추출
- `frontend/src/api/todoApi.ts`: health와 Todo endpoint 함수
- `frontend/src/api/types.ts`: 생성된 OpenAPI 타입에 읽기 쉬운 별칭 제공
- `frontend/src/api/schema.d.ts`: OpenAPI에서 자동 생성되며 직접 수정하지 않는 파일

`api<T>()`는 `fetch`를 한 곳에서만 사용한다. JSON body가 있으면 Content-Type과 직렬화를 처리하고, 2xx가 아니면 Problem Details를 읽어 `ApiError`를 던진다. 오류 응답이 JSON조차 아닐 때도 `HTTP_ERROR` 기본 객체를 만들어 화면 코드가 항상 같은 방식으로 처리할 수 있다.

`App.tsx`는 더 이상 `fetch`와 응답 구조를 직접 다루지 않는다.

```text
getHealth() + listTodos()
  -> api<T>()
  -> 성공: 생성된 TypeScript 타입으로 반환
  -> 실패: ApiError(detail, code, traceId)
```

화면에서는 Problem Details의 사용자 메시지와 요청 ID를 표시할 수 있다.

## 7. OpenAPI 계약과 타입 생성

`openapi/openapi.yaml`에 OpenAPI 3.1 계약을 추가했다.

포함된 endpoint:

- `GET /actuator/health`
- `GET /api/todos`
- `POST /api/todos`
- `GET /api/todos/{id}`

포함된 schema:

- HealthResponse
- CreateTodoRequest
- TodoResponse
- TodoPageResponse
- ProblemDetail
- ValidationProblemDetail

생성 명령:

```powershell
npm.cmd run openapi:generate --prefix frontend
```

`openapi-typescript`가 계약을 읽어 `frontend/src/api/schema.d.ts`를 만든다. `check-openapi.mjs`는 메모리에서 타입을 다시 생성하고 커밋 대상 파일과 비교한다. 따라서 개발자가 YAML을 바꾸고 타입 생성을 잊으면 `npm run check`와 CI가 실패한다.

설치 시 최신 `openapi-typescript 7.13.0`이 TypeScript `^5.x`를 peer dependency로 요구하는 것을 확인했다. 강제 설치 대신 TypeScript를 호환되는 최신 5.x인 5.9.3으로 고정했다. Vite·React 소스에는 TypeScript 6 전용 문법이 없어 기능 변화는 없으며 npm 감사 결과 취약점은 0건이었다.

## 8. Todo HTTP 통합 테스트

`TodoApiIntegrationTests.java`는 MockMvc, Spring Security Test, Testcontainers PostgreSQL을 함께 사용한다. 단순 단위 테스트가 아니라 Security filter, Controller, Validation, JPA, Flyway가 연결된 상태로 검사한다.

검증 항목:

1. Todo 목록은 인증 없이 조회 가능하고 페이지 메타데이터를 반환함
2. 인증 없는 Todo 생성은 401 Problem Details를 반환함
3. 개발 계정으로 인증하면 Todo를 생성하고 감사 시간이 채워짐
4. 공백 제목은 필드 오류가 있는 VALIDATION_ERROR를 반환함
5. 깨진 JSON도 REQUEST_ERROR와 traceId를 반환함
6. 실제 3개 항목에서 size 2 페이징과 전체 개수가 정확함
7. 없는 UUID는 TODO_NOT_FOUND를 반환함
8. size 101은 검증 오류로 차단됨
9. 안전한 클라이언트 요청 ID가 응답까지 그대로 전달됨

기존 ApplicationContext 기동 테스트, CORS preflight, Actuator 공개·보호 범위 검증을 포함해 전체 백엔드 테스트는 12개다. 각 테스트 DB는 PostgreSQL 17 Testcontainer에서 실행되며 Flyway V1~V3와 Hibernate schema validation을 통과했다.

프론트에는 Vitest/Testing Library 테스트 3개를 추가했다. API client가 Bearer token과 `X-Request-Id`를 보내고 Problem Details를 `ApiError`로 변환하는지, Todo page가 TanStack Query 결과를 렌더링하는지 확인한다.

## 10. 유지보수 규칙

- 새 도메인 오류는 `ApiException`을 상속하고 안정적인 대문자 오류 코드를 부여한다.
- Controller에서 예외를 JSON으로 직접 변환하지 않고 `GlobalExceptionHandler`에 맡긴다.
- 새 Entity가 같은 생성·수정 시간 정책을 사용할 때만 `BaseTimeEntity`를 상속한다.
- 목록 endpoint는 데이터가 커질 수 있으면 `PageResponse`를 사용하고 최대 size를 제한한다.
- 백엔드 API 요청·응답을 변경하면 `openapi/openapi.yaml`도 같은 작업에서 수정한다.
- OpenAPI 변경 후 `npm run openapi:generate`를 실행하고 생성 파일을 함께 커밋한다.
- 프론트 화면에서 직접 `fetch`를 반복하지 않고 `api` 및 도메인 API 모듈을 사용한다.
- 장애 문의 시 응답의 `traceId` 또는 `X-Request-Id`로 서버 로그를 검색한다.

## 11. 범용 기본 세팅 보강

후속 작업에서 특정 Todo 기능이 아니라 새 프로젝트의 공통 출발점에 해당하는 구성을 추가했다.

- 백엔드: `local`, `test`, `prod` profile 분리, 운영 OIDC JWT Resource Server, Prometheus registry, readiness/liveness, graceful shutdown
- 프론트: React Router, TanStack Query, access token provider, 전역 오류 경계, 404 page, API·컴포넌트 테스트
- 운영: Java와 Nginx 비루트 multi-stage 이미지, `compose.prod.yaml`, `.env.example`, SPA proxy와 보안 헤더
- 품질: Docker Compose 문법 검사, CI의 운영 이미지 build job, job timeout/concurrency, Dependabot
- 저장소: `.editorconfig`, 비밀값·캐시·build 결과 ignore, 선택형 Redis profile

OpenAPI의 쓰기 endpoint는 로컬 Basic과 운영 Bearer JWT를 대안 인증 방식으로 명시한다. 프론트 타입은 계약 변경 후 다시 생성했다.
